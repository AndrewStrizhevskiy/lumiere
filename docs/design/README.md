# Design record

How Lumière's interface was designed and refined. These are **records, not user documentation**; the shipped behaviour is described in the main README and the documents under `docs/`.

* [LUMIERE_DESIGN.md](LUMIERE_DESIGN.md): the design system (palette tokens, typography, accessibility review, logo exploration). Parts describe explorations that were not adopted (for example the outlined wordmark, later removed).
* [CRAFT_DIRECTION.md](CRAFT_DIRECTION.md): the guiding principles ("a small independent cinematheque", typography first, no simulated textures) and a checklist for future design decisions.
* [TITLE_CLEANER.md](TITLE_CLEANER.md): rules and limits of the offline title cleaner used by "Continue watching".
* [HISTORY_MODEL_PROPOSAL.md](HISTORY_MODEL_PROPOSAL.md): a proposal (not implemented) for representing several videos of one torrent.
* [CONTINUE_WATCHING_AND_INTERACTION_PROPOSAL.md](CONTINUE_WATCHING_AND_INTERACTION_PROPOSAL.md), [PHASE0_AND_INTERACTION_IMPLEMENTATION.md](PHASE0_AND_INTERACTION_IMPLEMENTATION.md), [R1_R6_IMPLEMENTATION_CHECKLIST.md](R1_R6_IMPLEMENTATION_CHECKLIST.md): working documents of the implementation, kept for history.
* `screens/`: screenshots (offscreen Qt renders with made-up titles; `after/` is regenerated by `prototypes/render_screens.py`, `before/` shows the earlier look).
* `prototypes/`: `render_screens.py` renders the screenshots; `craft_mock.py` is a superseded mock kept for history.

> **Naming of the code in these records:** they were written when the packages were called `kino_stream` / `kino_stream_ui` and the commands `kino-stream` / `kino-stream-gui`; today these are `lumiere` / `lumiere_ui` and `lumiere` / `lumiere-gui` (see [docs/NAMING.md](../NAMING.md)). Paths and identifiers in these documents are left as they were written.
